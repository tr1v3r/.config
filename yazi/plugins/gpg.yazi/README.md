# gpg.yazi

Yazi 内的签名加密与验签解密插件。

## 使用

- `c e`：签名加密；多选时合并打包，成功后删除源项目。
- `c b`：批量签名加密；每个选中项生成独立密文，成功后分别删除源项目。
- `c k`：存档式签名加密；沿用 `c e` 的打包规则并保留源项目，无冲突时直接执行。
- `c s`：为一个或多个普通文件分别创建独立的 `.sig` 签名，保留源文件。
- `c d`：逐个解密并验证一个或多个 `.gpg` 文件，成功项删除对应密文。
- `c v`：独立验签一个或多个 `.gpg` / `.sig` 文件，不恢复或删除任何文件。

对应的插件参数为：

```text
encrypt
encrypt --each
encrypt --keep
encrypt --each --keep
sign
decrypt
verify
```

当前使用两个独立的完整指纹：

```text
recipient: 899318F5A4423B72DF6A166FE4AF5FF89222F261
signer:    C633910E8F351365DEAAF300046263C39890F916
```

## 行为

- 单个普通文件：生成 `<文件名>.gpg`。
- 单个目录：先打包，再生成 `<目录名>.tar.gz.gpg`。
- 默认多选：只接受同一父目录下的项目，合并为一个可命名的 `.tar.gz.gpg`。
- `--each`：逐项处理；单个文件生成 `.gpg`，单个目录分别生成 `.tar.gz.gpg`。
- `--keep`：密文安全落盘后保留源项目；可与 `--each` 组合。目标不存在时不弹窗，存在时确认后原子替换。
- 多选 `--keep` 自动使用 `<当前目录名>.tar.gz.gpg`，避免额外的命名弹窗；删除源项目的默认模式仍可自定义包名。
- `sign`：逐个生成二进制 detached signature `<文件名>.sig`；始终保留源文件，目录不参与签名。
- 新文件始终同时签名和加密；解密时签名者必须匹配配置的完整指纹。
- 双收件人密文可由任一匹配的本机私钥解密，不要求配置的 `recipient` 私钥必须在本机。
- 删除源项目的加密模式和解密恢复模式遇到目标冲突时停止，不覆盖。
- 独立签名首次生成时不确认；已有同名 `.sig` 时才要求输入 `y`，确认后原子替换旧签名。
- 加密文件安全落盘后才删除原项目；恢复完成后才删除密文。
- 多选解密逐项执行；某个密文失败时会保留该密文并继续处理其余项目，最后统一汇总。
- 旧的无签名 `.gpg` 仍可解密，但必须在警告框中准确输入 `legacy`。
- 独立验签只接受有效且匹配 `signer` 的签名；无签名 legacy 文件会报告失败。
- 验证 `.sig` 时会自动查找去掉 `.sig` 后的同名源文件，例如 `report.pdf.sig` 对应 `report.pdf`。
- 验证 `.gpg` 时会解开加密层以验证内嵌签名，但明文标准输出会被直接丢弃，不写入文件。

删除源项目的加密和解密操作会要求输入 `y`；保留源项目的加密及独立签名只在覆盖同名目标时确认，独立验签不需要确认。

## 依赖

- `gpg`
- `tar`
- 对应公钥
- 加密时可用的签名私钥或智能卡 stub
- 解密时可用的解密私钥或智能卡 stub

```sh
./tests/gpg-smoke.sh
```
